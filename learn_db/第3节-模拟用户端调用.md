# 第 3 节：模拟用户端调用

## 【本节目标】

- 理解"用户端"和"数据库"之间为什么要隔一层，这一层叫**接口**。
- 亲手写一个 `client.py`，把 SQL 全藏起来，对外只露出几个函数。

---

## 【核心概念讲解】

### 比喻：餐厅的后厨和菜单

前两节，你既是厨师又是传菜的——自己在后厨写 SQL，自己把数据端出来。

但真实的软件不是这么干的：

- **后厨** = 数据库（存着所有食材和数据）
- **食客** = 用户端（一个网页、一个 App、或者别人写的另一个程序）
- **菜单 + 服务员** = 接口（interface）

食客**不进后厨**，他只看菜单："来一份 `get_user(1)`"，服务员进去端出来。食客完全不需要知道后厨用的是什么灶、什么锅。

所以你前面写的 `INSERT INTO users ...` 这些 SQL，**不应该出现在用户端的代码里**。用户端只说"我要加个人"，至于底层是 SQLite 还是 MySQL、SQL 怎么写，是服务员的事。

### 这一层有什么用

最直接的好处：**换数据库时，用户端一行都不用改。**

今天我们偷偷把 MySQL 换成了 SQLite，你写的用户端代码如果已经封装好了，根本感觉不到。这就是"分层"最朴素的威力——把变化关在一个盒子里，别的地方不受影响。

## 【动手应用】

在 `d:\python\my_agent` 下新建 `client.py`，自己敲：

```python
import sqlite3


class UserDB:
    """对 users 表的所有操作，全部关在这个类里"""

    def __init__(self, db_path="shop.db"):
        self.conn = sqlite3.connect(db_path)
        self.conn.row_factory = sqlite3.Row   # 让查询结果能按列名取值
        self.cur = self.conn.cursor()

    def add_user(self, name, age, city):
        """加一个用户，返回他的新 id"""
        self.cur.execute(
            "INSERT INTO users (name, age, city) VALUES (?, ?, ?)",
            (name, age, city))
        self.conn.commit()
        return self.cur.lastrowid

    def get_user(self, user_id):
        """按 id 查一个人，查不到返回 None"""
        self.cur.execute("SELECT * FROM users WHERE id = ?", (user_id,))
        row = self.cur.fetchone()
        return dict(row) if row else None

    def list_users(self, min_age=0):
        """列出年龄 >= min_age 的所有人，按年龄排序"""
        self.cur.execute(
            "SELECT * FROM users WHERE age >= ? ORDER BY age", (min_age,))
        return [dict(r) for r in self.cur.fetchall()]

    def delete_user(self, user_id):
        """删一个人，返回实际删掉了几条"""
        self.cur.execute("DELETE FROM users WHERE id = ?", (user_id,))
        self.conn.commit()
        return self.cur.rowcount

    def close(self):
        self.conn.close()


# ================= 下面是"用户端"，它完全不懂 SQL =================
if __name__ == "__main__":
    db = UserDB()

    new_id = db.add_user("小李", 28, "深圳")
    print("新加的用户 id =", new_id)

    print("小李的信息：", db.get_user(new_id))

    print("所有 18 岁以上的人：")
    for u in db.list_users(18):
        print("  ", u["id"], u["name"], u["age"], u["city"])

    n = db.delete_user(new_id)
    print("删掉了", n, "条")

    db.close()
```

跑起来：

```bash
cd /d/python/my_agent
python client.py
```

预期输出大概是：

```
新加的用户 id = 4
小李的信息： {'id': 4, 'name': '小李', 'age': 28, 'city': '深圳'}
所有 18 岁以上的人：
   1 小明 18 杭州
   2 小红 22 上海
   3 老王 35 北京
   4 小李 28 深圳
删掉了 1 条
```

跑完再看一眼数据库，`小李` 已经被删干净了——**这就是一次完整的"用户端增删查"**。

### 想验证"调用"这件事？

再开一个终端窗口，运行：

```bash
python -c "from client import UserDB; db=UserDB(); print(db.list_users())"
```

看到了吗？你不用写任何 SQL，只要 `from client import UserDB`，就能拿到数据。**这就是"别人调用你的数据库"的真实样子。** 以后换成 HTTP 接口，也只是把"函数调用"换成"发个网络请求"，本质一样。

## 【易错点提醒】

1. **`rowcount` 不能用来数 SELECT 的结果**。它只在 INSERT / UPDATE / DELETE 后有意义（表示影响了几行）。查数量要用 `len(fetchall())` 或者 `SELECT COUNT(*)`。
2. **`dict(row)` 会报错**：如果你忘了在 `__init__` 里写 `self.conn.row_factory = sqlite3.Row`，`row` 是普通元组，`dict()` 不了。这个设置必须写在 `connect()` 之后、任何 `execute()` 之前。
3. **忘记 `close()`**：脚本跑一次看不出问题，但程序长时间运行时连接不关会越积越多。养成习惯：用了就关。
